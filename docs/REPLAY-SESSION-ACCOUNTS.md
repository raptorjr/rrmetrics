# Replay sessions as virtual accounts — proposed next milestone

Status: first implementation covers session overview/create, one-instrument replay, versioned checkpoints and separate trades, full-window workspace and account balances. Independent chart symbols are implemented for context and the user confirmed on Babylon that selection, synchronized Go to, symbol-scoped drawings, execution-only orders, and save/restore work. Shared analytics remains outstanding. Remaining sections describe target architecture. Baseline: development 9873f28, with interactive replay trading, scaling and SQLite-backed chart display preferences.

## Product requirements

- Backtesting opens Replay sessions by default, with Create session and a leading play button to start/resume. Multiple independent sessions may be unfinished at the same time. Leaving a session pauses it, not completes it.
- List: name, description (optional), historical range, starting balance, current balance, realized P/L, completed trades, win rate, progress and status. Filters All / In progress / Completed. Use existing RR Metrics visual conventions.
- Create dialog: required name, historical start/end date and time, positive USD starting balance; optional description. No symbol selection at creation. Strategy linkage and reusable layout templates are later additions. Offer convenient balance presets, not required.
- Derive selectable ranges from the imported OHLCV catalogue, not calendar guesses. At least one supported instrument/contract must cover the chosen interval; expose coverage gaps and distinguish partial coverage. Chart symbol picker shows markets with usable data for the range, using contract/source identity to prevent mixing contracts.
- The replay list has a three-dot menu with Rename and confirmed Delete. Both mutations are owner- and revision-scoped; deletion removes only the chosen virtual account and its cascaded replay trades, never imported historical data or broker/manual records. A later Statistics action will select the session's stable virtual account ID in Backtesting mode and navigate to Dashboard once the shared analytics projection and selector exist.
- Session is an independent account, with immutable ID and editable display name. It owns its execution history, account balance and replay state. It is not a broker connection or a real trading account.
- Account selector gets Trading / Backtesting modes with separate remembered selections. Trading includes actual imported/manual trading accounts, including prop evaluations and practice accounts. Backtesting includes replay sessions, including empty sessions. Never combine the modes, even when All is selected. Same dashboard/analytics tiles and calculation code, separate data scope. Keep dashboard layout independent of the mode.
- Save centrally to SQLite, not localStorage. Resume on another device with the same session.

## Architecture and constraints found in source

- Existing legacy backtesting_sessions/backtesting_trades are a manual journal with one active session and win/loss/R data, not execution records. Preserve them unchanged and separately accessible. Never fabricate prices, money or fill history for these rows.
- Existing trades table and getTrades API are used by broker imports, reconciliation, manual editing, account management and statistics. Keep simulated records isolated in dedicated replay tables, and map them through a shared analytics trade contract rather than inserting into broker-owned trades or relying on a name filter. Use explicit source/domain and stable replay-session account key; carry signed direction, quantity, timestamps, explicit gross/net P/L, fees (zero until modeled), risk/R, and fills. Audit each metric for missing values and correct signed quantity convention before enabling it. No fake broker IDs or evaluation flags. Scope every read/write by owner and domain. Use account catalogues rather than deriving replay accounts from trades alone.
- DashboardPage and AnalyticsPage already accept filtered trades; reuse these. Audit their other inputs and side effects (broker sync, add/edit real trades, evaluation filter, calendar notes, strategy tags, exports and account management). Disable or scope non-applicable actions in Backtesting mode. Don't let a global All or empty selection fall back to Trading.
- Current replay state is ephemeral in BacktestingReplayWorkspace, and changing market/range/timeframe resets it. A saved session fixes the historical range; changing chart timeframe or symbol must not clear executions, balances or the replay clock.
- ChartWidgetGrid.captureLayout()/restoreLayout() includes arrangement, active chart, sync and parked charts; individual widget capture includes symbol, interval, chart state/settings. Verify drawings, indicators, price/time viewport and per-symbol drawing state via real round-trip tests; capture any missing state separately. Restore only host-authorized symbols/timeframes and revealed data, never restore a native trading/replay engine or future candles.
- Current grid uses one ticker/series and one net position with one working order. Multi-symbol context is a distinct change: each chart loads its own eligible series and shares one authoritative timestamp. Orders must belong to their instrument; initially one execution instrument at a time, context charts cannot submit to the wrong instrument; changing execution instrument while exposed must be blocked or require flattening. Later independent per-symbol positions/pending orders if explicitly scoped. Same-symbol multi-timeframe layouts remain supported throughout.

## Dedicated replay workspace

- Starting or resuming a session opens an edge-to-edge workspace using the full available browser viewport width and height. Hide the normal RR Metrics navigation/sidebar, page title, outer cards and redundant page padding while replay is open; normal navigation returns on exit.
- Use one compact horizontal header: **Save & exit** (back arrow) on the far left, session name and account information (starting balance, current balance, equity, realized P/L and unrealized P/L) in the middle, and a fullscreen toggle on the far right. Session selector and account metrics form one framed centered group. Side columns remain independent of saving status so the group does not jump. Session switching saves first; routine successful saves are silent, with progress and errors visible. No separate account-statistic cards above the chart. Keep the row compact with responsive overflow or prioritized values on narrow screens.
- The chart grid consumes all remaining available width and height alongside the compact existing order panel; replace the fixed chart height with a responsive, resizable flex layout. Keep replay controls compact below the charts, and make secondary statistics/trade history accessible without permanently reducing chart height (e.g. collapsible lower history panel and always-visible bottom-aligned order-panel statistics). Preserve the existing chart toolbar, layout selector, indicators and order interaction.
- Fullscreen means the entire replay workspace (account bar, charts, order panel and replay controls), not just one chart. Use the browser Fullscreen API on explicit user action; reflect actual fullscreen state and support Escape/native exit. Leaving fullscreen does not exit or complete the session; fullscreen itself is device-local and not restored automatically. Standard edge-to-edge mode remains usable if the browser denies fullscreen.
- Save & exit pauses replay, captures current chart/session state, waits for the server to acknowledge the latest checkpoint, and then returns to the session overview. Failed saves or revision conflicts leave the workspace open with a clear retry path. Exiting does not flatten a position, cancel orders or mark the session completed. Intercept other in-app navigation away when unsaved changes remain.
- Verify desktop and laptop sizes, normal/fullscreen transitions, chart resize and independent viewport preservation, and save/exit/resume from fullscreen. Do not reintroduce the old layout-selector or candle-recentering regressions.

## Durable state

Use additive migrations and new owner-scoped tables for replay session metadata, versioned checkpoints, and immutable/stable-id completed trade and execution records. Account ID is session ID. Metadata includes name, description, chosen historical range (UTC), starting cash in USD cents, status, timestamps, current checkpoint revision.

Checkpoint includes last revealed execution timestamp and stable source provenance (dataset identities, resolution, content/version fingerprints as supported), current execution market, replay speed, paused state, active chart and full grid layout, indicators, drawings, viewports, orders, position, realized partial exits, current order sequence/IDs, selected contract size and draft order type/price. Global preferences remain profile-scoped. Persist closed trade and fills alongside checkpoint in one transaction, idempotently; no duplicated closes after retries or restore. Use optimistic revision checks to prevent two devices silently overwriting each other. On opening restore paused, reload only the historical data needed for revealed time, then apply saved view and orders. Never auto-advance or auto-fill on restore. Handle deleted or changed source data explicitly: preserve saved trades and stats; block replay continuation if the original historical context cannot be reconstructed. Do not silently substitute another contract or revised data. Historical source rows are not copied into a session unnecessarily.

Autosave meaningful changes (including drawing edits, orders, fills and progress) with bounded/debounced checkpoint writes, serialize saves and visibly surface unsaved/error/conflict states. Explicit Save & exit pauses and awaits latest successful save before leaving. Browser unload is best effort, not a durability guarantee. Test refresh, second device, concurrent revisions, interruptions, stale writes, idempotent fills, missing sources, empty sessions and no lookahead.

## Account balances

Starting balance is a virtual cash baseline, not a margin model. Balance = starting balance + all realized P/L, including realized partial reductions of still-open round trips. Equity = balance + remaining unrealized P/L. Display balance, equity, starting balance and realized/unrealized P/L together in the single compact workspace header. Completed trade metrics remain one round trip per flat position; balance incorporates partial exits immediately, without counting them twice when flat. Keep cents and known currency; current simulation is gross of fees/slippage, explicitly labeled. Do not imply buying power, leverage or liquidation rules before a risk/margin model exists. Combining sessions aggregates trades; balance/equity and return metrics must use their respective baselines and explicitly defined aggregation rather than concatenating unrelated equity curves.

## Delivery sequence

1. Add new persistent session metadata, isolated virtual account identity, starting balance and coverage-aware create/list UI. Preserve legacy manual journal.
2. Integrate existing replay workspace into a selected session; versioned checkpoint, atomic trades/fills, save/exit/resume with cross-device and interrupted-save regression tests. Build the edge-to-edge workspace and compact account bar with Save & exit and workspace fullscreen. Verify complete chart state capture and restore. No placeholder sessions claiming resume before this works.
3. Replace the workspace's independent date/market controls with session range and catalogue-driven chart symbol selection. Introduce shared timestamp and per-chart symbol data, ensure orders are instrument-scoped, preserve prior viewport/selector/drag behavior.
4. Add common analytics projection and account popup Trading/Backtesting switch, independently persisted selection, empty sessions, hard data isolation, reuse Dashboard and Analytics; audit metric and action compatibility. Verify real account results are unchanged and no simulated data leaks to broker paths. Extend balance tiles and session summaries using shared calculations.
5. Browser and cross-device acceptance tests on Babylon. Later: multi-instrument execution, session duplication, strategy version association, chart templates, history overlays, costs and risk/margin modeling.

First implementation deliberately restricts the period to a single base-resolution dataset and locks the execution market once replay or trading starts or a checkpoint is saved. Chart layout state uses TradeCanvas capture/restore; independent horizontal and manual price viewport and drawing synchronization use the updated TradeCanvas fork and need real browser verification. Trading/Backtesting analytics mode remains unimplemented. Independent chart symbols use one shared execution timestamp and contract-specific sources; trading stays confined to the locked execution instrument.

## First-version refinements

Restart is explicitly confirmed and revision-checked, clears only the selected simulated account's orders and trades, restores starting cash, clears drawings and viewport, and keeps indicators/layout. Time-based replay speed is independent of chart interval, with 60× equaling one minute of active-market time per wall-clock second. Brighter labels and loading overlay, centered playback controls, bottom-aligned statistics, and same-symbol drawings across intervals.
